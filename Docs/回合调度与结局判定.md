# 余音 · 回合调度器 + 结局判定

## 一、回合调度器（GameFlow）

`Assets/Scripts/Core/GameFlow.cs` 负责「什么时候轮到谁」，一轮固定五步：

| 步骤 | 阶段 | 谁负责 | 结束方式 | 事件 |
| --- | --- | --- | --- | --- |
| ① 场景状态 | `RoundStart` / `SceneState` | 框架 | 自动（沿用上一轮的不回家 + 随机补物品） | `RoundStartedEvent` / `SceneStatePhaseEvent` |
| ② 玩家输入 | `PlayerInput` | 玩家 / 物品系统 | 玩家碰一次 → `RegisterPlayerTouch` | `PlayerInputPhaseEvent` |
| ③ 物品状态 | `ItemSettle` | 物品 / 数值系统 | 自动 | `ItemSettlePhaseEvent` |
| ④ 住户行为 | `NpcAction` | NPC 行为系统 | 触碰旁白播完 → 镜头动画拉远 → 演出完成 → `NotifyNpcActionDone` | `NpcActionPhaseEvent` |
| ⑤ 回家 / 不回家 + 轮次+1 | `RoundEnd` | NPC 行为系统判定，框架收尾 | 自动 | `RoundEndedEvent` |

> 第 6 轮结束后先判**母亲开门**（知晓 > 60 → 暖意至少 61、知晓至少 63，并收走她所有东西），再结算结局。

### 一轮的实际时间线

```
住户都在门里 → 随机摆几件物品 → 玩家碰一次 → 住户出行动 → 
行动结束：先判有没有人不回家，再判是谁 → 
  没被留下的人走回门口；被留下的人进入「区域持续」，停在原地，该区域下一轮不可用
```

- **第 1 轮开始**：没有上一轮的判定，所以全员在家（在门里）。
- **场景状态阶段**：`ItemSystem.EnsureSceneItems(区域, sceneItemCount)` 从物品池**随机**摆几件到该区域的
  空闲放置点，保证玩家有东西可碰（`GameConfig.sceneItemCount`，默认 3；母亲物品本次不参与）。
- **住户只在玩家碰过之后行动**：玩家输入阶段结束才进 NPC 行动阶段。
- **不回家判定在行动结束之后**，结果通过 `GameSession.SetAbsentDecision` 留给**下一轮**：
  下一轮的玩家阶段里那个区域不可用，玩家可以强碰。

### 不回家判定（先判有没有，再判是谁）

`Assets/Scripts/Core/TurnRules.cs`：

```csharp
// 第一步：80% 有 1 人不回家 / 20% 全员在家
TurnRules.ShouldSomeoneStayOut(random, config);

// 第二步：是谁（只在能行动的住户里挑，母亲永远不中）
TurnRules.TryPickWhoStaysOut(random, session.residents, out ResidentId absent);

// 两步合起来（NpcSystem.ResolveEndOfRound 用的就是这个）
TurnRules.TryPickAbsentResident(random, config, session.residents, out ResidentId absent);
```

判定入口：`NpcSystem.ResolveEndOfRound()`（住户行动结束后由 `NpcPhaseDriver` 调用）。
结果通过 `RoundEndedEvent` / 下一轮的 `RoundStartedEvent` 广播；
那个人置为「区域持续」，停在他当时所在的区域，并 `ItemSystem.SetAreaBlocked(区域, 住户)`
让该区域在下一轮不可用。玩家强碰他，或者下一轮他回家，都会解除。

### 与表现层同步节奏

- `GameConfig.phaseStepDelay`（默认 **0.2 秒**）：每个阶段之间留的时间，让相机 / 门光 / UI 跟上。
  设 0 就是每阶段一帧。暂停（`Time.timeScale = 0`）时整条流程一起停。
- `GameConfig.npcActionStepDelay`（默认 0.35 秒）：NPC 每两个行动之间的间隔。
- `GameConfig.npcPhaseTimeout`（默认 30 秒）：NPC 行动阶段没人汇报完成时的兜底。
- 玩家输入阶段和 NPC 行动阶段是**等条件**的（等玩家碰、等 NPC 演完），其余阶段是定时节奏点。
- 玩家触碰后，`NpcPhaseDriver` 先等 `NarrationState.IsTouchNarrationPlaying` 结束（最多 12 秒，
  `Space` 可逐句跳过），再让 `SceneStitcher` 用动画把镜头拉到拼接全场景；行动结束再动画拉回单场景。

## 二、结局判定（EndingRules）

本次 Demo 不做结局界面，但判定已经写成**纯函数 + 单测**：
`Assets/Scripts/Core/EndingRules.cs`。

```csharp
EndingResult result = EndingRules.Resolve(session, config); // 档位 + 标题 + 判定依据
EndingId id = EndingRules.ResolveId(session, config);       // 只要档位
string title = EndingRules.TitleOf(id);
```

第 6 轮结束、`GameFlow.EndGame()` 时会算一次并打日志（方便提前验证数值）：
`[结局判定] 雨没停（所有人的暖意与知晓都在低档）`。

### 判定档位

**高 = 数值 > 60，低 = 数值 ≤ 60**；小女孩的知晓度不参与判定
（`GameConfig.highThreshold = 60`）。「除母亲外所有人」= 老婆婆 + 大叔。

| 结局 | 母亲 | 老婆婆 / 大叔 | 小女孩暖意 |
| --- | --- | --- | --- |
| 告别 | 知晓高 + 暖意高 | 全都知晓高 + 暖意高 | 不限 |
| 互相隐瞒 | 知晓高 + 暖意高 | 知晓高、暖意低 | 不限 |
| 只有母亲一个人知道 | 知晓高 + 暖意高 | 全都低 | 不限 |
| 谁也没开口 | 知晓高、暖意低 | 知晓高 | 不限 |
| 全楼都知道了，却没人敢告诉母亲 | 低 | 全都知晓高 + 暖意高 | 不限 |
| 谁也没开口 | 低 | 知晓高、暖意低 | 不限 |
| 整栋楼都不知道他已经死了 | 低 | 知晓低、暖意高 | 不限 |
| 雨没停 | 低 | 全都低 | 低 |
| 只有小女孩还记着他 | 低 | 全都低 | 高 |

### 已知的文档分歧

两份文档对「谁也没开口」的归属不一致：

- `余音_文档整合.md` 4.6：母亲**知晓 > 60、暖意 ≤ 60** + 邻居都高。
- `余音_系统设计.md` 八：「母亲低 + 邻居知晓高、暖意低」。

代码里**两种情况都判成「谁也没开口」**（见 `EndingRules` 的 ② / ③ 分支），
另外把文档没覆盖的组合（母亲开门但邻居知晓低暖意高）兜底成「只有母亲一个人知道」。
确认口径后改 `EndingRules.Resolve` 一处即可。
