# 余音 · 数据流（谁读谁写）

对应：程序分工 7.3「数据流：明确谁读谁写」。本文按**当前实现**写，不是设计意图。

## 一、分层与数据归属

### 单一出口清单（改代码前先看这张表）

| 数据 | 唯一出口 | 现状 |
| --- | --- | --- |
| 暖意 / 知晓度 | `StatSettlement`（只有它调 `GameSession.AddWarmth / AddAwareness`） | ✅ 无双写（例外：`ApplyGirlMovedItem` 顺手清物品温度） |
| 音频（音量 / 音效 / BGM / 雨声） | `AudioManager` | ✅ UI 只转发；`BGMManager` 已删（原为死代码） |
| 暂停 / 继续 | `PauseDirector` | ✅ UI 与 ESC 都走它；设置是暂停场景内的面板 |
| `Time.timeScale` | `GameFlow`（Pause / Resume / StartNewGame） | ✅ 其他地方不直接写 |
| 角色美术（尺寸 / 脚底线 / 排序） | `CharacterArtConfig` + `YuyinArtTool`（编辑期刷进 prefab / 场景） | ✅ 运行时只读 |
| 阶段（`TurnPhase`） | `GameFlow.Phase` 属性 | ✅ 阶段事件已删，看属性即可 |
| 一局进度 | `GameSession`（常驻） | ✅ 场景只绑引用，不搬数据 |
| 切场景状态 | `SceneTransitionState`（现在放 `Core/`） | ✅ `PauseDirector` 也读它来决定能不能暂停 |

```
GameRoot（常驻，DontDestroyOnLoad）
 ├─ GameConfig / GameText / SfxLibrary / CharacterArtConfig   配置（编辑期填好，运行时只读）
 ├─ GameSession        一局的数据：轮次 / 住户 / 物品 / 全局计数
 ├─ RandomService      唯一随机源
 ├─ StatSettlement     暖意 / 知晓度 **唯一**加减法出口
 ├─ ItemSystem         物品池 / 温度 / 放置 / 区域占用
 ├─ NpcSystem          住户状态机 + 行动决策
 ├─ GameFlow           五阶段调度 + GameState / TurnPhase
 ├─ NpcPhaseDriver     行动阶段的**演出**：走位、进出场、开门关门
 ├─ SceneStitcher      拼接两个场景（静态状态）
 ├─ AudioManager       音频唯一出口（音量真值 + PlayerPrefs）
 ├─ PauseDirector      暂停唯一出口
 ├─ NarrationDirector / IntroNarration / PromptOverlay / DebugOverlay
 └─ SceneFadeOverlay   切场景黑幕（读 SceneTransitionState）

场景（每个游戏场景一个 GameManager）
 └─ 只做绑定：把 ResidentView / ItemView 接到 GameSession 上；自身不存游戏数据
```

## 三、一轮的数据流（和文档 7.3 的表对照）

| 步骤 | 谁主持 | 读 | 写 | 发的事件 |
| --- | --- | --- | --- | --- |
| ① 场景状态 | GameFlow + NpcSystem | 上一轮的不回家决定 | 住户 `state` / `isOut` / 区域占用；`EnsureSceneItems` 往玩家所在区域补 3 件 | `RoundStartedEvent`、`SceneStatePhaseEvent` |
| ② 玩家输入 | PlayerController + ItemSystem | 按键、物品状态、区域占用、本轮已碰次数 | `item.hasTemperature`；强碰时写 `Startled`、`forceTouchWarningsUsed` | `ItemTouchedEvent` / `ItemPromptEvent` / `ForceTouchWarnedEvent` |
| ③ 物品结算 | GameFlow（自动） | 温度 | ——（温度的加减在②就做完了；真正数值在④） | `ItemSettlePhaseEvent` |
| ④ 住户行为 | NpcSystem 决策 + NpcPhaseDriver 演出 | 住户状态、物品位置、放置点 | 住户数值（经 StatSettlement）、`state`、`currentX`；拿回写 `item.hasTemperature` / `isInPool`；小女孩移动写 `item.area/placementId` | 每步 `NpcActionEvent`；状态变化 `NpcStateChangedEvent`；进出场 `NpcDoorEvent` + `NpcMovedEvent` |
| ⑤ 轮次收尾 | NpcSystem + 驱动 | 回家判定 | `absentResident` / `hasAbsentResident`、`isOut=false` + 关门 | `RoundEndedEvent` |
| ⑦ 母亲开门（第 6 轮后） | `StatSettlement.ResolveMotherDoorAtEnd` | 母亲知晓 | 母亲暖意 61；`CollectMotherItems` 收她的物品 | `ItemTakenEvent` |
| ⑧ 结局 | `EndingRules`（纯函数） | 四人暖意 / 知晓 | —— | `GameOverEvent`（**当前无人订阅**） |

> 和文档 7.3 的两处差异：③ 物品结算在实现里没有独立逻辑（温度在②标好、数值在④结算）；② 的"惊吓标记"实际是写 `NpcState.Startled`（不是独立布尔）。

## 四、几条支线的数据流

- **玩家触碰链**：`PlayerController` → `GameManager.OnPlayerTouch` → `ItemSystem.Touch` → 数值走 `StatSettlement` → 事件 → `ItemView.RefreshVisual` / `PromptOverlay` / `AudioDirector`。表现层不写玩法数据。
- **NPC 回家链**：`NpcSystem.ResolveEndOfRound`（定谁不回家）→ `NpcPhaseDriver.WalkHome`（走位 + `isOut=false` + 关门）→ 下一轮 `NpcSystem.BeginRound` 复位其余字段。
- **暂停链**：`PauseDirector.PauseGame` → 相机重渲染抓图 → `PauseSnapshot.Store` → `GameFlow.Pause`（`timeScale=0`）→ `LoadScene("Pause")`；`PauseScreen` 只读快照画背景，按钮回调 `PauseScreen.OnResumeClicked/OnQuitClicked` 或 `PauseMenuUI`（设置面板）。
- **切场景链**：`ScenePortal2D` → `SceneTransitionState.BeginLoad` + 淡出 → 异步加载 → `SceneFadeOverlay.OnSceneLoaded` 收尾 → `GameManager.Bind` 把新场景 View 接回同一份 `GameSession`。
- **美术链**：`CharacterArtConfig`（编辑期）→ `YuyinArtTool` 刷 prefab + 场景 → 运行时 `ResidentView` / `PlayerController` 只读自己的 `SpriteRenderer`。

## 五、事件通道

| 通道 | 用在哪 |
| --- | --- |
| `EventBus`（结构体事件） | 玩法 → 表现/音频/UI 的**主要**通道（物品、NPC 行动/状态、门、数值、回合、结局） |
| `GameSession` 上的 C# 事件（`WarmthChanged` / `AwarenessChanged` / `NpcStateChanged`） | **目前零订阅**（同一个变更 EventBus 也发了一份） |
| 直接调用 | 场景内：`GameManager` ↔ `PlayerController`；常驻：`PauseDirector` ↔ `PauseScreen`（按钮回调）；UI ↔ `AudioManager` |

| 范围 | 活在哪 |

## 七、梳理时发现的问题

| # | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| 1 | `isOut` 有**两个写者**（`NpcSystem` 逻辑 + `NpcPhaseDriver` 演出） | "谁在外/在家"没有单一事实来源，之前"回合结束集体消失"就是这里出来的 | 把 `isOut` 收归 NpcSystem；驱动只发"我演到哪了"的请求，不直接改数据 |
| 2 | `StatSettlement` 越界写 `ItemData.hasTemperature`（小女孩移动清温度） | 数值系统碰了物品状态，和"所有加减法都在 StatSettlement"的边界说法混在一起 | 让 ItemSystem 负责清温度，或明确写一句"结算有权清温度"并保留 |
| 3 | `GameRoot.LoadDebugSnapshot()` 读快照后**不回绑视图**（`Session.LoadSnapshot` 会换掉 residents/items 列表，View 还拿着旧引用） | F1"读取快照"显示的是旧数据，误导调试 | load 之后调一次 `Scene.Bind()`（一行） |
| 4 | `touchesThisRound` 三个写点（复位 / GameFlow 正路 / ItemSystem 兜底） | 正常只走前两个，兜底那条只该在没有 GameRoot 时用 | 保持现状即可，但建议补注释说明 |
| 5 | `PlacementRegistry` 是跨层静态：运行时和编辑器工具共用 | 工具跑完不还原会污染编辑器里的场景逻辑 | 保持"工具用完还原"的约定（美术工具已做；模拟器只清占用） |
| 6 | `PauseSnapshot` 的纹理**由读方 `PauseScreen` 释放** | 职责别扭；若暂停场景被以别的方式卸载，释放时机不可控 | 让 `PauseDirector` 统一持有/释放（`Store` 已有兜底释放） |
| 7 | `GameClockUI` 的累计时间是 UI 私有状态 | 玩法侧拿不到"本局用时" | 若以后要进结局/存档，需把它挪进 `GameSession` |
| 8 | `playerInputDone` 只在触碰次数用满时置位，`NotifyPlayerInputDone()` 还没有调用方 | 玩家所在区域没有"没碰过"的物品时，回合会一直停在 PlayerInput | 无物可碰时主动调 `NotifyPlayerInputDone()` |
| 9 | 母亲物品全是 `startsInScene=false`，补货又跳过 Mother | "碰母亲物品 → 疑惑"和 `CollectMotherItems` 实际走不到 | 若要启用母亲机制，需要给她一条上架路径 |
| 10 | `ItemSettle` 阶段目前空转（温度在触碰时已写） | 阶段名容易误解 | 保留为节奏点，或在文档里明确说明 |

## 八、方向（谁调谁 / 谁告诉谁 / 谁可以认识谁）

这三条是**不同的箭头**，混在一起看就会误判。下面按"正常方向 → 事件落点 → 反向箭头"排。

### 8.1 三个方向

| 方向 | 走法 | 规矩 |
| --- | --- | --- |
| **调用方向** | 输入 → 调度 → 逻辑 → 数据：`PlayerController → GameManager → ItemSystem → GameSession / StatSettlement`；`GameFlow` 按回合向下驱动 | 逻辑层**不反向调表现层** |
| **通知方向** | 数据 → 事件 → 表现 / 音频 / UI：`GameSession / ItemSystem / NpcSystem` 只 `Publish`，表现层只 `Subscribe` | 单向广播，订阅方**不反写**玩法数据 |
| **依赖方向** | `Data / Config` 被所有人引用；`Views → Core`；**`Core` 不引用 `Views`** | 唯一例外：常驻的 `NpcPhaseDriver` 是"表现桥"，它引用 View |

### 8.2 事件落点（通知方向的终端）

| 事件 | 谁在听 |
| --- | --- |
| `ItemTouched` / `ItemTaken` / `ItemAppeared` / `ItemMoved` | `ItemView`（刷新显隐/微光）、`AudioDirector`（音效）、`NarrationDirector`（独白） |
| `ItemPrompt` / `ForceTouchWarned` | `NarrationDirector` / `PromptOverlay`、`AudioDirector` |
| `NpcDoor` | `AudioDirector`（开关门音）、`NarrationDirector`（教学） |
| `NpcAction` | `AudioDirector`（交流时雨声断一拍） |
| `NpcStateChanged` / `NpcMoved` | `ResidentView`（显隐 / 位置） |
| `RoundStarted` / `NpcActionPhase` | `NpcPhaseDriver`（自己驱动行动阶段） |
| `RoundEnded` | `NarrationDirector` |
| `GameStateChanged` | UI / 表现 |
| `Narration` / `NarrationClear` / `InteractHint` / `PortalHint` | `PromptOverlay` |

### 8.3 反向 / 越界箭头清单（这是"数据方向"真正要盯的）

| 方向 | 位置 | 性质 |
| --- | --- | --- |
| 表现 → 数据 | `NpcPhaseDriver` 写 `ResidentData.isOut` | ⚠️ 和 `NpcSystem` 抢同一个字段（双写者） |
| 表现 → 数据 | `NpcPhaseDriver` 写 `currentX / hasCurrentX / groundY / hasGroundY` | ⚠️ 这几个"数据"字段只有表现层在写 |
| 数值 → 物品 | `StatSettlement.ApplyGirlMovedItem` 写 `item.hasTemperature` | ⚠️ 越界（数值系统碰物品状态） |
| 读方 → 生命周期 | `PauseScreen.OnDestroy` 释放 `PauseSnapshot.Texture` | ⚠️ 谁写谁释放的规矩被倒过来了 |
| 表现 → 静态状态 | `SceneFadeOverlay` 调 `SceneStitcher.ResetStatics()` | ⚠️ 轻耦合，可接受但要知道 |
| 物品 ↔ 调度 | `ItemSystem` 调 `flow.CanPlayerInteract / RegisterPlayerTouch`，而 `GameFlow` 又持有 `ItemSystem` | ⚠️ 双向依赖（同层，能跑，但以后拆模块会咬手） |
| 逻辑 → 没用上 | `NpcSystem` 存了 `flow` 却从不使用 | ⚠️ 假依赖，删掉更干净 |
| 逻辑 → 无接收方 | `GameSession` 的 `WarmthChanged / AwarenessChanged / NpcStateChanged` | ⚠️ 死箭头（EventBus 已有一份） |
| 调试 → 玩法 | `DebugOverlay` 改温度、强制推进阶段、开关暂停 | ✅ 明确的调试口（F1），保持隔离即可 |

### 8.4 推还是拉

- **推（事件）**：数值、物品、NPC 行动/状态、门、回合、结局 —— 都是"变了就广播"。
- **拉（每帧轮询）**：`PlayerController` 每帧扫本场景 `ItemView` 找可碰目标；`DebugOverlay` 每帧读 `GameSession`；**UI 的暂停按钮每帧查 `PauseDirector.CanPause`**（现在没有"可暂停状态变化"事件，接 UI 只能轮询 —— 记一笔）。
- **半推半拉**：`ResidentView` 由事件触发刷新，但"位置防漂移"顺手在 `RefreshVisual` 里做。

### 8.5 跨边界的三个方向

| 边界 | 方向 |
| --- | --- |
| 切场景 | 场景内 View → `GameManager.Bind` → 常驻 `GameSession`：**只重新绑引用，不搬数据** |
| 暂停 | 常驻 `PauseDirector` → 抓图 → `PauseSnapshot`（常驻）→ 暂停场景**只读**；回来时 `PauseSnapshot` → `PlayerController` 还原站位 |
| 落盘 | `AudioManager` → `PlayerPrefs`（音量/静音）；UI → `PlayerPrefs["Brightness"]`；调试面板 → JSON 快照。**玩法数据不落盘** |
