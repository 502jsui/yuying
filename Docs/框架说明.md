# 余音 · 整体框架 / 基础设施说明

本文档说明当前框架各模块的职责、接入方式，以及其他人做玩法 / 表现 / UI 时应该从哪里接。

## 一、分层

```
GameRoot（常驻，自动创建）
 ├─ GameConfig        配置（ScriptableObject）
 ├─ RandomService     可复现随机
 ├─ GameSession       一局的数据（体力值 / 物品 / 轮次）
 ├─ GameFlow          顶层状态机 + 每轮五阶段
 ├─ EndingDirector    三档结算演出 + 现有 HUD 临时隐藏 / 恢复
 ├─ AudioManager      音频与音量
 └─ DebugOverlay      调试面板（F1）

场景
 └─ GameManager       场景绑定器：把本场景 View 接到 GameSession
```

要点：

- **数据不在场景里**。`GameSession` 挂在常驻的 `GameRoot` 上，所以切场景不会丢进度。
- **场景里的 `GameManager` 只做绑定**。它不会创建数据，只把 `ResidentView` / `ItemView` 接到 `GameSession`。
- **玩法系统之间不互相引用**，统一通过 `EventBus` 发事件。

代码程序集：

| 程序集 | 目录 | 说明 |
| --- | --- | --- |
| `Yuyin.Runtime` | `Assets/Scripts` | 运行时逻辑 |
| `Yuyin.Editor` | `Assets/Scripts/Editor` | 编辑器工具 |
| `Yuyin.Tests.EditMode` | `Assets/Tests/EditMode` | 纯逻辑单测 |
| `Yuyin.Tests.PlayMode` | `Assets/Tests/PlayMode` | 运行时冒烟测试 |

## 二、每轮流程（GameFlow）

`GameFlow` 负责推进，顺序固定为：

```
RoundStart → SceneState（不回家判定）→ PlayerInput → ItemSettle → NpcAction → RoundEnd
```

> 阶段之间的节奏由 `GameConfig.phaseStepDelay`（默认 0.2 秒）控制；
> 玩家输入阶段等玩家碰一次，NPC 行动阶段等 `NotifyNpcActionDone`（超时 30 秒兜底）。
> 详细的回合调度 + 结局判定见《回合调度与结局判定.md》。

| 阶段 | 谁负责 | 怎么结束 |
| --- | --- | --- |
| RoundStart | 框架 | 自动 |
| SceneState | 框架 | 自动（用 `TurnRules` 判定不回家） |
| PlayerInput | 玩家 / 物品系统 | 玩家碰一次，`GameFlow.RegisterPlayerTouch(itemId)` |
| ItemSettle | 物品 / 数值系统 | 自动 |
| NpcAction | NPC 行为系统 | 演出完成后调用 `GameFlow.NotifyNpcActionDone()` |
| RoundEnd | 框架 | 自动，轮次 +1；第 6 轮后进入 Ending |

给其他系统的接口：

```csharp
// 玩家是否可移动 / 可触碰
GameRoot.Instance.Flow.CanPlayerMove
GameRoot.Instance.Flow.CanPlayerInteract

// 玩家碰物品（先由物品系统判断是否合法）
GameRoot.Instance.Flow.RegisterPlayerTouch(itemId);

// NPC 行为系统演完一轮后汇报
GameRoot.Instance.Flow.NotifyNpcActionDone();
```

> `NpcAction` 阶段有超时兜底（`GameConfig.npcPhaseTimeout`，默认 30 秒），
> 没有任何系统汇报完成时会打警告并强制进入下一阶段，避免卡死。

## 三、事件（EventBus）

订阅示例：

```csharp
private void OnEnable()  { EventBus.Subscribe<NpcMovedEvent>(OnNpcMoved); }
private void OnDisable() { EventBus.Unsubscribe<NpcMovedEvent>(OnNpcMoved); }

private void OnNpcMoved(NpcMovedEvent evt)
{
    // evt.id / evt.from / evt.to / evt.placementId
}
```

已有事件（`Core/GameEvents.cs`）：

| 事件 | 用途 |
| --- | --- |
| `GameStateChangedEvent` | 主界面 / 游戏中 / 暂停 / 结束 |
| `RoundStartedEvent` / `RoundEndedEvent` | 轮次开始 / 结束 |
| `NpcActionPhaseEvent` | NPC 行动阶段开始（驱动自己订阅来开演） |
| `ItemTouchedEvent` / `ItemTakenEvent` / `ItemMovedEvent` | 物品系统对外广播 |
| `NpcStateChangedEvent` | NPC 状态切换 |
| `NpcMovedEvent` / `NpcDoorEvent` | 住户换区域 / 开门关门 |
| `ItemPromptEvent` / `ForceTouchWarnedEvent` / `InteractHintEvent` / `PortalHintEvent` | 提示与警告（物品触碰 / 场景门） |
| `NarrationEvent` / `NarrationClearEvent` | 统一提示通道（教学 / 独白 / 拒绝）；清屏用于逐句跳过 |
| `NarrationState.IsTouchNarrationPlaying` | 触碰旁白是否在播（NPC 阶段等它结束再拉镜头） |
| `GameOverEvent` | 结束结算：携带 `EndingResult`，由 `EndingDirector` 自动播放三档演出并回主菜单 |

> 阶段（`TurnPhase`）不再广播事件：要看当前阶段直接读 `GameFlow.Phase`（Action 循环里轮询即可）。
> 暖意 / 知晓度也不再各自广播事件，需要时读 `GameSession` 或走玩法事件。

## 四、数据（GameSession / Data）

`GameSession` 字段：

| 字段 | 说明 |
| --- | --- |
| `seed` | 本局随机种子 |
| `round` | 当前轮次 1~6 |
| `residents` | 住户数据（暖意 / 知晓度 / 物品池 / 行动次数 / 状态） |
| `items` | 物品数据（主人 / 类型 / 位置 / 区域 / 温度 / 已收回） |
| `forceTouchWarningsUsed` | 本轮强碰警告已用次数（每轮 2 次，`GameSession.BeginRound` 复位） |
| `touchesThisRound` | 本轮已触碰次数 |
| `absentResident` / `hasAbsentResident` | 本轮不回家的住户 |

常用方法：

```csharp
session.GetResident(ResidentId.Grandma);
session.GetItem("grandma_01");
session.EnsureItem(id, owner, type);      // 没有就创建，场景绑定用
session.AddWarmth(id, delta, config);     // 自动夹取 + 发事件
session.AddAwareness(id, delta, config);
session.HasItemInPool(ItemOwner.Grandma); // 还有没有没拿出来的东西
session.GetItemsInArea(AreaId.FirstFloor);
```

## 五、配置（GameConfig）

- 资产路径：`Assets/Resources/GameConfig.asset`
- 菜单：`Tools → 余音 → 创建或选中默认配置`
- 文档 4.7 的参数都在这里，改数值不需要动代码。
- 运行时找不到资产会自动用代码默认值兜底，不会崩。

## 六、随机（RandomService）

所有概率必须走 `GameRoot.Instance.Random`，不要直接用 `Random.Range`：

```csharp
random.Chance(0.35f);
random.RangeInclusive(2, 3);
random.PickWeighted(items, weights);
random.Reseed(12345);   // 复现某一局
```

同一个种子能复现同一局，方便查 bug 和写单测。

## 七、音频 / 存档 / 调试

- `AudioManager`：主音量 / 音乐 / 音效，雨声断拍用 `TriggerRainPause()`。
  雨声、UI 音 Clip 填在 `GameConfig` 里。
- `SessionStore`：调试用的一局快照（JSON），存到 `Application.persistentDataPath/yuyin_session.json`。
- `DebugOverlay`：游戏里按 **F1** 打开，可以看状态 / 改轮次 / 重开 / 存读快照。

## 七点五、场景与屏幕等大（相机规范）

- 相机固定、不跟随玩家。
- **整个场景 = 一屏**：设计尺寸按 16:9 的 `19.2 × 10.8` 世界单位
  （正交尺寸 5.4，`19.2 = 2 × 5.4 × 16/9`）。
- 一楼和二楼的可视层高是 `4.8`，两层叠起来约等于后院 `10.8` 的高度；
  单场景仍使用 `19.2 × 10.8` 的相机画幅，宽镜头拉远后按整栋楼取景。
- `SceneCameraFollow2D` 根据场景矩形自动取景：

  ```
  size = max(场景高 / 2, 场景宽 / (2 × 屏幕宽高比))
  ```

  这样整个场景一定可见，并且在 16:9 下刚好铺满屏幕、不留边。
- 场景内容（背景、门、地面、传送门）由 `Tools → 余音 → 重建基础场景` 生成，
  默认就是按这个一屏尺寸排的：
  - 一楼：三扇门在 x = -6 / 0 / 6；
  - 后院：传送门在 x = -8.6；一楼通往后院 / 二楼的出口与二楼楼梯都在右侧 x = 8.6；
  - 玩家左右边界 x ∈ [-9, 9]。
- NPC 行动阶段由 `SceneStitcher` 把整栋楼拼起来，`SceneCameraFollow2D` 用动画拉远 / 拉回；
  雨场同步覆盖整栋楼，雨丝落到二楼屋顶线以下隐藏，屋顶在雨层上方显示；
  开场独白则先推近主角，独白结束再回到单场景取景。
- 目标分辨率是 16:9。其他宽高比下会保证“整个场景可见”（可能上下或左右多出一点背景），
  如果要严格铺满，需要再做分辨率适配（可另开任务）。

## 九、其他系统的接入点

| 系统 | 接入方式 |
| --- | --- |
| 物品系统 | 用 `GameSession.EnsureItem` 建数据；触碰成功后调 `Flow.RegisterPlayerTouch`；发 `ItemTakenEvent` / `ItemMovedEvent` |
| NPC 行为 / 状态机 | 已实现：`GameRoot.Instance.Npc`（`NpcSystem`）+ `NpcPhaseDriver`。驱动订阅 `NpcActionPhaseEvent`，按 `npcActionStepDelay` 逐个执行行动，播完自动调 `Flow.NotifyNpcActionDone()`；状态变化走 `GameSession.SetNpcState`，每个行动广播 `NpcActionEvent`。详见《NPC系统说明.md》 |
| UI | 订阅 `GameStateChangedEvent`；阶段要看 `GameFlow.Phase`（不再有阶段事件） |
| 自检 | `Tools → 余音 → 自检`（或 `-executeMethod YuyinSelfCheckTool.RunFromCommandLine`）：一把过 Build Settings / 场景 / prefab / 配置 / 母亲开关 / 门缝光接线 |
| 相机 | 已按《相机规范》在 `SceneCameraFollow2D` 里实现“固定 + NPC 行动拉远” |
| 门 / 灯光 | `DoorLightView.Apply(warmth, awareness, hasAwareness)`，阈值可在 Inspector 调 |
| 角色美术 | `Assets/Resources/CharacterArt.asset` + `Tools → 余音 → 应用角色美术`；详见《美术接入说明.md》 |
| 暂停 | `PauseDirector`（常驻）+ `Scenes/Pause.unity`；UI 挂 `PauseScreen` 的三个回调；详见《暂停说明.md》 |
| 主界面 | 接好后把 `GameConfig.autoStartOnSceneLoad` 改成 false，由开始按钮调 `GameRoot.Instance.StartNewGame()` |

## 十、当前假设（需要确认）

1. 暖意 / 知晓度上限按 **0~100** 处理（文档只写了 60 档位，没写上限）。
2. `autoStartOnSceneLoad` 默认 **true**，进游戏场景就直接开局，方便现在测试；主界面接入后改 false。
3. 相机默认 **固定不跟随**，场景按一屏（16:9，`19.2 × 10.8`）设计，
   单层画面铺满屏幕；NPC 行动会拼接整栋楼并动画拉远成 `38.4 × 21.6` 宽画幅。
4. 二楼是玩家可探索的母亲线原型：二楼只服务玩家与母亲，NPC 不跨楼层。
   NPC 行动阶段会把二楼以 `+4.8` 叠在一楼正上方、后院接在一楼右侧，形成整栋楼的宽镜头；玩家在二楼时，
   镜头仍然拉远看整栋楼，一楼 / 后院的住户会在各自副本里完整演出行动。
