# 余音 · 结局分布模拟器（程序分工 7.4）

对应：程序分工 7.4（命令行模拟器 + 结局分布验收）、七天计划 第 3 / 4 / 6 天。

## 一、文件

| 文件 | 职责 |
| --- | --- |
| `Assets/Scripts/Core/GameSimulator.cs` | 不开画面的整局模拟 + 汇总（纯逻辑） |
| `Assets/Scripts/Editor/YuyinSimulatorTool.cs` | 菜单 / 命令行入口、参数解析、写报告 |
| `Assets/Tests/EditMode/GameSimulatorTests.cs` | 8 条单测：可复现、分布自洽、四种玩家策略都能跑完 |

它把 `GameFlow` + `NpcPhaseDriver` 的一轮流程按同样的顺序重跑一遍，但不生成任何场景物体，
用的是真正的 `ItemSystem` / `NpcSystem` / `StatSettlement` / `EndingRules`，
所以跑出来的分布就是**当前数值下的真实分布**。

一轮的顺序（和 `GameFlow.RunRound` 一致）：

```
① 场景状态（住户回家 / 上一轮定下的「谁不回家」）
② 摆物品（EnsureSceneItems，摆在玩家所在区域）+ 玩家碰一次
③ 物品结算（温度在触摸时就标好，这一步没有额外逻辑）
④ 住户行动（先判 ForceTakeOutNext，再逐个住户 RollActionCount → DecideNextAction → Execute）
⑤ 轮次 +1；一轮结束后 ResolveEndOfRound 定下下一轮谁不回家
6 轮走完 → 母亲开门 →（收走母亲的物品）→ 结局判定
```

**不模拟**：渲染、走位时长、音效、开门动画、相机、拼接场景。

## 二、怎么跑

### Unity 菜单

- `Tools → 余音 → 结局分布模拟`：跑 500 局，结果写到
  `Docs/Simulation/结局分布.md` 和 `Docs/Simulation/结局分布.csv`
- `Tools → 余音 → 结局分布模拟（单局明细）`：跑 1 局，打印逐轮明细（调 bug 用）

菜单跑之前会先把场景注册的放置点存一份，跑完还原，不会影响打开着的场景。

### 命令行

```powershell
& "D:\unity\test\2022.3.62f3\Editor\Unity.exe" -batchmode -nographics -quit `
  -projectPath "E:\unity\咕咕嘎嘎" `
  -executeMethod YuyinSimulatorTool.RunFromCommandLine `
  -simRuns 500 `
  -simOut "E:\unity\咕咕嘎嘎\Docs\Simulation\结局分布.md" `
  -simCsv "E:\unity\咕咕嘎嘎\Docs\Simulation\结局分布.csv" `
  -logFile "E:\unity\咕咕嘎嘎\Logs\sim.log"
```

退出码：`0` = 验收通过，`1` = 验收不通过（可以用来卡 CI），`2` = 跑挂了。

> 注意：跑测试的那条命令**不要**加 `-quit`（会和 Test Runner 抢退出）；
> 跑 `-executeMethod` 这条加 `-quit` 没问题。

### 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-simRuns` | 500 | 跑多少局 |
| `-simSeed` | 1 | 起始种子；第 n 局的种子由它派生，同参数同结果 |
| `-simPolicy` | `insist` | 玩家策略，见下 |
| `-simOut` | 无 | 报告写成 markdown |
| `-simCsv` | 无 | 分布写成 csv |
| `-simTraceGames` | 0 | 打印前几局的逐轮明细 |
| `-simTrace` | -1 | 只打印第 n 局（从 0 开始） |
| `-simMaxShare` | 0.6 | “最大结局占比”上限 |
| `-simMinShare` | 0.15 | “最小结局占比”下限 |
| `-simNoMinShare` | — | 跳过“最小占比”这一条 |
| `-simAllowMissing` | — | 允许有结局出现 0 次 |
| `-simIgnoreMother` | — | Demo 口径：母亲不参与（没人找她、她不开门；结局只剩“母亲低”的 5 档） |

玩家策略（`-simPolicy`）：

| 值 | 行为 |
| --- | --- |
| `stay` | 一直待在一楼；本区域被「区域持续」的住户占着就不碰，这一轮空过 |
| `insist`（默认） | 一直待在一楼；被占就一直按，前两次被警告、第三次强碰生效 |
| `roam` | 每轮随机换一楼 / 后院；被占就不碰 |
| `roaminsist` | 每轮随机换区域；被占就强碰 |

玩家一轮只能碰一次，所以“碰哪件、认不认怂”本身就会明显改变分布；四种都跑一遍就知道结论稳不稳。

### 覆盖数值（看分布调数值用）

只覆盖写了的字段，其余沿用 `Resources/GameConfig.asset`：

`-simWander -simTalk -simTakeOut -simTakeBack -simGirlMove -simTalkMother -simAbsent`
`-simWarmTake -simAwareTake -simAwareTakeCold -simWarmTalk -simAwareTalk -simAwareTalkMother -simGirlWarm`

例：把“拿到没温度的东西”的知晓度从 15 改成 5，看分布怎么动：

```powershell
-simRuns 500 -simAwareTakeCold 5
```

## 三、验收线本身有个数学问题

程序分工 7.4 写的是：每个结局都出现过、最大 ≤60%、最小 ≥15%。

但本次 Demo 有 **8 个结局**：8 × 15% = 120% > 100%，**这条不可能同时满足**。
模拟器会把这句话直接打在报告里，并且按“最小占比”那条判失败。

要往下走，得先定一个能算的验收线，三个选项：

1. 只要求“每个结局都出现过 + 最大 ≤60%”（把 15% 那条去掉）；
2. 保留 15% 下限，就把结局数量压到 ≤6 个；
3. 给每个结局单独定目标占比（比如“告别 ≥5%、雨没停 ≥10% …”）。

数值是策划的口径，模拟器只负责把真实分布摆出来。

## 四、当前分布（2026-10-11，500 局，起始种子 1）

默认策略（留在一楼 / 被占就强碰）：

| 结局 | 次数 | 占比 |
| --- | ---: | ---: |
| 告别 | 1 | 0.2% |
| 互相隐瞒 | 89 | 17.8% |
| 只有母亲一个人知道 | 30 | 6.0% |
| 谁也没开口 | 308 | 61.6% |
| 全楼都知道了，却没人敢告诉母亲 | 3 | 0.6% |
| 整栋楼都不知道他已经死了 | 0 | 0.0% |
| 雨没停 | 22 | 4.4% |
| 只有小女孩还记着他 | 47 | 9.4% |

出现过的结局 **7 / 8**；最大 61.6%（“谁也没开口”）已经压过 60% 的上限；
“最小 ≥15%”不通过。母亲开门 24.0%（母亲只被大人的交流喂知晓度）。

`roam` 策略（随机换区域 / 被占就不碰）下是 7 / 8，最大是“谁也没开口”53.4%——
两种策略都缺同一个结局。这条策略不会强碰，所以也不会触发“小女孩被强碰”那条路，数字一直很稳。

### 为什么「整栋楼都不知道他已经死了」是 0 次

这个结局要求：**老婆婆和大叔都暖意 >60、且至少有一个知晓 ≤60**。

- 暖意 >60：从 26 起步，只能靠“拿到有温度的东西”+18 攒（交流只 +4），所以每人至少要**2 次拿到有温度的东西**；
- 知晓 ≤60：拿到东西 +15、被交流 +8。2 次拿到东西就是 50，再被交流 1 次就 58，第 2 次就 66 出线了。

也就是说，这个人必须**正好拿到 2 次有温度的东西，且几乎不被交流**，两个人都得这样。
而实测平均每局只有 **1.3~1.9 次**“拿到有温度的东西”（两个人加起来），
小女孩还会把温度清掉。所以这不是代码分支坏了（`EndingRulesTests` 里 8 个结局都有用例），是**数值上够不到**。

要让它出现，能动的是“有温度的物品”的供给：

- 每轮玩家触碰次数（现在 1 次/轮）；
- 小女孩移动物品的权重（现在 20，实测每局清掉 2.9~3.3 次温度）；
- “拿回东西”的权重（现在 20）；
- 拿到东西加的知晓度（现在固定 +15，是知晓度飙升的主因）。

这些都属于策划的数值口径，改之前建议先跟策划对一遍。

## 五、顺带发现的两件事

1. **一楼只有 1 个「别的物品上」放置点**（`first_on_item`），而药包 / 工具包 / 木雕都只能放在“别的物品上”，
   所以这三件最多同时在场 1 件，住户“拿出东西”会经常走到 `PlacementBlocked` 的失败分支
   （代码注释里本来就想要这个“放不下”的演出，不算 bug，但会明显影响物品流转速度）。
2. 玩家所在区域被占的轮次很多（不回家 80%/轮），默认策略下平均每局要**强碰生效 3.3 次**、
   正常触碰只有 2.7 次——也就是说“强碰”不是罕见操作，是常规操作，这会持续扣暖意（每次 −8）。
