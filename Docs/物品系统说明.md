# 余音 · 物品系统说明

本文档说明物品系统的分层、数据、规则，以及其他系统（NPC 行为 / 表现 / UI / 场景配置）应该怎么接。

对应设计文档：第二章「物品安排 / 物品放置规则」，第三章「玩家能做的只有一件事」，
第四章「物品的流转 / NPC 状态 / 玩家输入 → 对应输出」。

## 一、文件与分层

| 文件 | 职责 |
| --- | --- |
| `Data/ItemData.cs` | 物品运行时数据（已有的框架字段） |
| `Data/ItemPlacement.cs` | `PlacementSurface` 放置面 + `ItemPlacementRules` 放置规则 |
| `Core/ItemSystem.cs` | 物品系统主逻辑：物品池、温度、碰、拿回、移动、区域占用 |
| `Core/ItemActionResult.cs` | 操作结果状态与提示文案 |
| `Config/GameConfig.cs` | `ItemConfig` 物品表 + 默认 9 件物品 |
| `Views/ItemView.cs` | 物品表现：微光、显示隐藏、吸附到放置点 |
| `Views/PlacementPoint.cs` | 场景放置点（placementId / area / surface） |
| `Managers/GameManager.cs` | 场景绑定 + 玩家触碰入口 |
| `Core/GameRoot.cs` | 持有 `GameRoot.Instance.Items` |

物品系统是**纯逻辑类**，不挂场景、不认 Prefab，只操作 `GameSession.items`。
表现与场景通过 `ItemView` / `PlacementPoint` / `EventBus` 接。

## 二、数据

### ItemData（运行时，一局内会变）

`itemId` / `owner` / `type` / `position` / `area` / `placementId` /
`hasTemperature` / `isInPool` / `isReturned`。

### ItemConfig（配置，写在 GameConfig.items）

| 字段 | 说明 |
| --- | --- |
| `itemId` | 唯一 ID。衣服 ×2、花盆 ×2 必须靠它区分 |
| `owner` | 主人 |
| `type` | 物品类型 |
| `startsInScene` | true 一开局就在场景里；false 先放物品池 |
| `startArea` | 开局所在区域（仅 startsInScene 有意义） |
| `startPlacementId` | 开局吸附到哪个放置点 |

## 三、放置规则（文档 2.6）

| 物品 | 允许的放置面 |
| --- | --- |
| 衣服 | 晾衣架（HangingRack） |
| 花盆 | 地面（Ground）/ 别的物品上（OnItem） |
| 药包 / 工具包 / 木雕 / 日记 | 别的物品上（OnItem） |
| 木箱 | 地面（Ground） |

规则实现：`ItemPlacementRules.CanPlace(type, surface)`。
没配置类型的物品（`ItemType.Unknown`）暂时允许任意放置面，避免接表现时被卡住。

## 四、物品池流转

```
未放出(池中) ──TakeOut──▶ 场景中(无温度)
                              │  ▲
                    Touch ────┘  │ Move(小女孩，清温度)
                              ▼  │
                          场景中(有温度)
                              │
                        Return(拿回)
                              ▼
                     已收回(不再出现)

母亲物品：场景中 → 有温度 → 保持（不会有人来收）
```

| 方法 | 谁调用 | 效果 |
| --- | --- | --- |
| `TakeOut(itemId, area, placementId, surface)` | NPC「拿出东西」 | 从池放到场景 |
| `TakeOutNext(owner, area, placementId, surface)` | NPC「拿出东西」 | 取该主人池里下一件 |
| `Return(itemId, by)` | NPC「拿回东西」 | 拿回并结算暖意 / 知晓度，之后不再出现 |
| `Move(itemId, by, area, placementId, surface)` | 小女孩 | 暖意 +18，清温度，物品留在场景 |
| `Touch(itemId)` | 玩家 | 见下一节 |
| `HasItemInPool(owner)` / `FindNextPoolItem(owner)` | NPC 行为系统 | 判断「拿出东西」还能不能发生 |

拿回结算（文档 3）：

- 有温度：暖意 +18、知晓度 +15
- 没温度：暖意 +0、知晓度 +15

## 五、玩家触碰（文档 4.4）

`ItemSystem.Touch(itemId)` 返回 `ItemActionResult`，带 `status` 和可以直接显示给玩家的 `message`。

| 情况 | status | 是否消耗本轮碰一次 |
| --- | --- | --- |
| 普通物品 | Success | 是 |
| 母亲物品 | Success | 是（并随机给 1~2 人「疑惑」） |
| 已有温度 / 二次触碰 | AlreadyTouched | 否（提示「你已经触摸过了」） |
| 不在场景（还在池里） | NotInScene | 否 |
| 本轮已经碰过 | TouchUsedUpThisRound | 否 |
| 不可用区域，前 2 次 | ForceTouchWarned | **否**（只弹警告） |
| 不可用区域，第 3 次起 | ForceTouchAccepted | 是（物品获得温度 + 该住户进入「惊吓」、暖意 −8） |

不可用区域由 NPC 状态机写入：

```csharp
GameRoot.Instance.Items.SetAreaBlocked(AreaId.FirstFloor, ResidentId.Aunt);
GameRoot.Instance.Items.ClearAreaBlocked(AreaId.FirstFloor);
```

## 六、事件（EventBus）

| 事件 | 何时发 | 谁订阅 |
| --- | --- | --- |
| `ItemTouchedEvent` | 玩家成功碰了一件物品 | 表现（微光）、音效 |
| `ItemAppearedEvent` | 物品从物品池被放到场景（「拿出东西」） | `ItemView`（显示并吸附到放置点） |
| `ItemTakenEvent` | NPC 拿回东西（带 hadTemperature） | 数值（可选）、UI |
| `ItemMovedEvent` | 小女孩移动东西 | 表现（位移动画） |
| `ItemPromptEvent` | 触碰被拒绝 / 有提示文案 | UI（「你已经触摸过了」） |
| `ForceTouchWarnedEvent` | 强碰还在警告阶段 | UI（警告对话框） |

## 七、NPC 行为系统接入

```csharp
ItemSystem items = GameRoot.Instance.Items;

// 「拿出东西」：先找一个满足放置规则的 PlacementPoint，再拿下一件
PlacementPoint point = ...;
ItemData next = items.FindNextPoolItem(ItemOwner.Aunt);
if (next != null && point != null && point.Accepts(next))
{
    items.TakeOut(next.itemId, point.area, point.placementId, point.surface);
}

// 「拿回东西」
items.Return(itemId, ItemOwner.Aunt.ToResidentId());

// 小女孩移动
items.Move(itemId, ResidentId.Girl, point.area, point.placementId, point.surface);
```

物品系统不主动推进回合；NPC 整套行动演完后仍然由 NPC 系统调
`GameFlow.NotifyNpcActionDone()`。

## 八、表现 / 场景接入

### 一键补齐：Tools → 余音 → 在当前场景补齐物品与放置点

打开 `FirstFloor` 或 `Backyard`，点这个菜单即可。它会：

1. 在场景里补出该区域的 `PlacementPoint`（一楼：`first_rack` / `first_ground_a~c` / `first_on_item`；
   后院：`backyard_ground_a~c` / `backyard_on_item`）；
2. 按 `GameConfig.items` 用 `Assets/Prefabs/Item_*.prefab` 生成 `ItemView`
   （开局在场景里的直接摆到放置点，其余先放到画面外的 `PoolStaging`，运行时被拿出后吸附到放置点）；
3. 把场景里所有 `ItemView` 自动填进 `GameManager.itemViews`；
4. 保存场景。

**幂等**：重复运行只会补缺失的对象，不会重复创建；
**已有同 `placementId` 的放置点会直接跳过**，所以你可以先把放置点拖到合适位置，
以后再跑这个菜单也不会被重置。放置点后期要改位置，直接在场景里拖 `PlacementPoints` 下的物体即可，
`ItemView` 运行时会自动吸附到新位置（也可以改 `anchor`）。

### 手动接法

- 放置点：空物体挂 `PlacementPoint`，填 `placementId` / `area` / `surface`，需要吸附就指定 `anchor`。
- 物品：Prefab 挂 `ItemView`，填 `itemId` / `owner` / `type` / `area`，拖进 `GameManager.itemViews`。
- `ItemView` 会按 `ItemData` 切微光、显隐、吸附到 `placementId` 对应的放置点；
  池里 / 已收回 / 不在本场景的物品会自动关掉碰撞体，玩家碰不到。

> 同一件物品在每个场景各有一份 `ItemView`，靠 `ItemView.area` 判断显示哪一份，
> 所以小女孩把东西挪到别的场景时，原来那份会自动隐藏、目标场景那份会出现。

## 九、GM 调试

`DebugOverlay`（游戏里按 F1）会显示每件物品的类型、位置、温度、是否收回，
并提供「把本区域物品全部标成有温度」等快捷按钮，方便验证拿回 / 移动逻辑。

## 十、测试

`Assets/Tests/EditMode/ItemSystemTests.cs` 覆盖：

- 默认物品表与开局场景 / 物品池分布
- 放置规则（衣服 / 花盆 / 药包 / 工具包 / 木雕 / 木箱 / 日记）
- 拿出被规则拦截、池空后不再拿出

## 十一、当前假设（需要确认）

1. **开局分布**：默认老婆婆的衣服、大叔的花盆已在一楼，其余 4 件在物品池；
   如果你想让 6 件全部在场景里、或全部在池里，改 `GameConfig.ApplyDefaultItems()` 即可。
2. **强碰警告不消耗本轮碰一次**：前 2 次只弹提示，玩家还能去碰别的；
   第 3 次起消耗本轮并产生温度。
3. **区域占用的区域**：由 NPC 状态机用 `SetAreaBlocked(area, resident)` 写入，
   物品系统不猜「谁住哪个区域」。
4. **母亲物品**：本次不做完整机制，但物品表和「碰母亲物品 → 疑惑」已经实现。
5. **温度跨回合 / 跨场景保留**：按文档理解为保留到被拿走或被小女孩移动。
